## 1. 背景と目的

### 1.1 背景

「1テーマにつき1枚、4〜6行、1分で書き切る」メモ書きトレーニングは、考えを寝かせずに即座に
言語化することで思考速度と言語化能力を高める手法として広く知られている。
一方、紙で実践する場合には次の課題がある。

- **継続の可視化ができない** — 何ページ書いたか、続いているかが分からない
- **蓄積が死蔵する** — 書いたメモが物理的に埋もれ、振り返りに使われない
- **タイトルが出てこない** — 「何を書けばいいか分からない」で手が止まる
- **振り返りの負荷が高い** — 数百枚のメモから傾向を読み取るのは現実的でない
- **手が追いつかない** — 思考速度に対して、手書き・タイピングが律速になる

### 1.2 目的

本アプリは、メモ書きの**実践（書く）を紙より軽くしながら**、紙では困難な
**蓄積・検索・振り返り**を支援することを目的とする。

軽さの中核を担うのが**音声入力**である。話す速度は書く速度より速く、
「思考を止めずに吐き出す」という手法の目的に最も近い入力手段であるため、
本アプリは音声入力を主たる入力手段として設計する。

### 1.3 成功指標（KPI 案）

| # | 指標 | 目標値（利用開始3ヶ月後） |
| --- | --- | --- |
| K-1 | 1メモあたりの平均記入時間（認識ラグを除く） | 60秒以内が全体の80%以上 |
| K-2 | 継続率（週3日以上メモを書いた週の割合） | 60%以上 |
| K-3 | 1日あたり平均作成メモ数 | 5ページ以上 |
| K-4 | 振り返り機能の月次利用 | 月1回以上 |

## 2. 設計思想

本アプリの機能取捨選択は、以下の原則を最優先で判断基準とする。
便利にしすぎると手法そのものが壊れるためである。

> **原則1：書いている最中に AI を介入させない。**
> メモ書きは「自分の頭で1分間ひねり出す」訓練である。執筆中のサジェスト・自動補完・添削は
> 手法の効果そのものを損なうため、**恒久的に対象外**とする。AI が働くのは書く前と書いた後だけ。

> **原則2：書き始めるまでの摩擦をゼロに近づける。**
> 起動から入力開始まで2アクション以内。ログイン・カテゴリ選択・設定を書く前に挟まない。

> **原則3：直すのは誤変換だけ。推敲はさせない。**
> 音声入力である以上、誤変換の修正は避けられない。しかし修正の窓を開けたままにすると
> 推敲が始まり、手法が壊れる。そこで**編集可能な期間を当日中に限る**（第6.1節 FR-06）。
> 日付が変わったメモは、書いたときのままの記録として確定する。

> **原則4：タイマーは思考時間だけを計る。**
> 音声認識の待ち時間は利用者の思考ではない。これを1分に含めるのは計測として誤りであるため、
> **計測は入力（発話）が止まった時点で停止**し、認識・保存に要したラグは計測に含めない。

## 3. 用語定義

| 用語 | 定義 |
| --- | --- |
| メモ | タイトル1行＋本文4〜6行からなる、1テーマ1枚の記録単位 |
| セッション | 連続してメモを書く一連の時間（既定：10枚 / 約10分） |
| お題（タイトル案） | これから書くメモのタイトル候補 |
| 深掘り | 書いたメモの内容から派生する次のメモのタイトルを導くこと |
| 振り返り | 一定期間に蓄積したメモを対象とした要約・傾向分析 |
| 目標時間 | 1枚あたりの目標記入時間（既定60秒） |
| ソフト上限 | 目標時間を超えたことを強く知らせる時点（既定90秒）。入力は止めない |
| 確定 | メモを保存し、編集可能期間に入ること |
| 認識ラグ | 発話停止から文字起こし結果が入力欄に反映されるまでの時間 |

## 4. スコープ

### 4.1 対象（本リリース）

- メモの作成・保存・一覧・検索・削除
- **音声入力による記入**（OS 標準の音声入力を利用）
- 目標時間タイマーとセッション管理
- AI によるお題出し・深掘り・振り返り（すべて明示的なボタン押下で起動）
- 1メモ1ファイルの Markdown による保存
- ローカル単一ユーザー利用（`streamlit run` によるローカル起動）

### 4.2 対象外（本リリース）

- 複数ユーザー / 認証 / チーム共有
- 手書き入力・OCR
- **アプリ内蔵の音声認識エンジン**（OS の音声入力に委ねる。第9.3節）
- モバイルネイティブアプリ
- クラウド同期・バックアップ
- 執筆中の AI サジェスト（原則1により恒久的に対象外）
- 編集履歴・バージョン管理（原則3により意図的に持たない）

## 5. 想定利用者と利用シーン

個人利用・非公開のため、ペルソナは単一とする。

| 項目 | 内容 |
| --- | --- |
| 像 | 思考の言語化速度を上げたい個人。既にメモ書き手法を知っている |
| 主な動機 | 頭に浮かんだことを、消える前に言葉にして残す |
| 主な障壁 | タイピングが思考に追いつかない。書いた紙が死蔵する。ネタが出ない日がある |
| 利用環境 | デスクトップ。マイクが常時使える静かな個室 |

### 代表的な利用シーン

1. **朝10分** — アプリを開き、AI にお題を10個出させ、順に1分ずつ話して書き切る。
2. **モヤモヤ発生時** — 思いついた瞬間にタイトルだけ打ち、本文は話して吐き出す。
3. **週末の振り返り** — 直近1週間のメモを AI に要約させ、繰り返し現れる論点を確認する。

## 6. 機能要件

優先度は MoSCoW（M=必須 / S=推奨 / C=可能なら）で示す。

### 6.1 メモ作成

| ID | 機能 | 内容 | 優先度 |
| --- | --- | --- | --- |
| FR-01 | メモ入力 | タイトル1行＋本文の入力。本文は4〜6行を推奨として提示 | M |
| FR-02 | 行数ガイド | 現在の行数を表示。3行以下／7行以上は注意表示（保存は妨げない） | S |
| FR-03 | 句点で自動改行 | 保存時、本文の句点（。）位置で改行に整形する。設定で OFF 可 | M |
| FR-04 | 確定保存 | `Ctrl + Enter` で確定し、即座に次の空メモへ遷移（連続記入） | M |
| FR-05 | 自動確定 | 最終入力から10秒間の無入力で自動確定。設定で秒数変更・OFF 可 | M |
| FR-06 | 当日中のみ編集可 | 確定後も、`created_at` が当日中のメモは本文・タイトルを編集できる。日付が変われば編集不可（削除は可） | M |
| FR-07 | 編集の記録 | 編集した場合 `edited_at` を記録する。編集前の内容は保持しない（原則3） | S |
| FR-08 | 削除 | 確定済みメモの削除は期間を問わず可能（確認ダイアログあり） | M |
| FR-09 | ドラフト随時保存 | 未確定の入力内容を5秒間隔で `data/.draft.md` に退避。確定時に削除 | M |
| FR-10 | ドラフト復帰 | 起動時に `data/.draft.md` が存在すれば、その内容を復元して再開できる | M |

**FR-03 の補足**：音声入力では話者が改行を意識しにくく、本文が1行に連なる。
句点での整形により、4〜6行という手法上の形を音声入力でも保つ。
「かいぎょう」等の OS 音声コマンドによる明示的な改行はそのまま尊重する。

**FR-06 の補足**：日付境界は 00:00 を既定とする。深夜に書く習慣がある場合に備え、
境界時刻を設定で変更可能とする（優先度 C）。

### 6.2 音声入力

| ID | 機能 | 内容 | 優先度 |
| --- | --- | --- | --- |
| FR-15 | 音声入力の受け入れ | OS 標準の音声入力（Windows: `Win + H` ／ macOS: 音声入力）で入力された文字を、通常のキー入力と区別なく受け付ける | M |
| FR-16 | 起動導線 | 入力欄の近くに、OS 音声入力の起動ショートカットを常時表示する | S |
| FR-17 | 入力方式の記録 | そのメモが音声主体かキーボード主体かを推定し `input_method` に記録する | C |
| FR-18 | 認識ラグの除外 | 認識結果がまとめて流入した場合も、経過時間は最終入力時点で止める（第6.3節 FR-21） | M |

**方式の選定理由**：アプリ内蔵の音声認識ではなく OS 標準機能を用いる。
理由は3つ。(1) 実装コストがゼロで、アプリは「文字が入ってくる入力欄」を持つだけでよい。
(2) 認識ラグが最小である。(3) 音声データが外部 API に送られないため、
第6.6節の「AI 送信はボタン押下のみ」という決定と矛盾しない。

### 6.3 タイマー

| ID | 機能 | 内容 | 優先度 |
| --- | --- | --- | --- |
| FR-20 | 計測開始 | 最初の1文字が入力された時点で計測を開始する | M |
| FR-21 | 計測停止 | 最終入力時点で計測を止める。認識・保存に要したラグは含めない（原則4） | M |
| FR-22 | 目標到達の合図 | 目標時間（既定60秒）到達時に色を変える。**入力はロックしない** | M |
| FR-23 | ソフト上限の合図 | ソフト上限（既定90秒）到達時に、より強い視覚的合図を出す。**入力はロックしない** | S |
| FR-24 | 経過の記録 | `elapsed_sec`（計測開始から最終入力まで）と `target_sec` を記録する。超過分は両者から導出する | M |
| FR-25 | 超過の可視化 | 一覧・振り返りで、目標時間を超えたメモを識別できるようにする | C |

**設計判断（Q-4）**：目標時間の超過で入力を打ち切らない。
打ち切ると、言いかけた1行が失われ、「吐き出し切る」という手法の目的に反するためである。
一方で無制限にすると制約が失われ手法が壊れるため、
「目標60秒 → ソフト上限90秒 → 10秒無入力で自動確定」の三段構えで、
強制ではなく合図によってペースを保つ。

### 6.4 セッション管理

| ID | 機能 | 内容 | 優先度 |
| --- | --- | --- | --- |
| FR-30 | セッション開始 | 目標枚数（既定10）を指定してセッションを開始 | S |
| FR-31 | 進捗表示 | 「3 / 10枚」の進捗と累計経過時間を表示 | S |
| FR-32 | セッション完了 | 目標達成時に完了サマリー（所要時間・平均秒数・超過枚数）を表示 | C |
| FR-33 | 連続日数 | 連続実施日数（ストリーク）と月間カレンダーを表示 | C |

### 6.5 蓄積・検索

| ID | 機能 | 内容 | 優先度 |
| --- | --- | --- | --- |
| FR-40 | メモ一覧 | 作成日時の降順で一覧表示。日付単位でグルーピング | M |
| FR-41 | キーワード検索 | タイトル・本文に対する部分一致検索 | M |
| FR-42 | タグ絞り込み | タグによる絞り込み | S |
| FR-43 | 期間絞り込み | 期間指定（今日 / 今週 / 今月 / 任意範囲） | S |
| FR-44 | 外部エディタとの併用 | アプリ外（Obsidian 等）でファイルが編集・追加された場合、次回起動時に取り込む | S |
| FR-45 | エクスポート | 選択範囲を1ファイルの Markdown に結合してダウンロード | C |

**FR-44 の補足**：ファイルが唯一の正であり、インデックス（第8.3節）はいつでも
再生成できるキャッシュに過ぎない。外部編集を壊さないことを設計上の制約とする。

### 6.6 AI 支援機能

**すべての AI 機能は、利用者がボタンを押した時にのみ起動する（Q-6 の決定）。**
自動実行・バックグラウンド送信は一切行わない。

| ID | 機能 | 入力 | 出力 | 優先度 |
| --- | --- | --- | --- | --- |
| AI-01 | お題出し | テーマ・悩み（自由文） | メモタイトル案10件 | M |
| AI-02 | 深掘り質問 | 直前に確定したメモ | 次に書くべきタイトル案3件 | M |
| AI-03 | 期間振り返り | 指定期間のメモ群 | 論点の要約・繰り返し現れるテーマ・気づき | M |
| AI-04 | モヤモヤ分解 | 漠然とした悩み1件 | 具体的な問いに分解したタイトル群 | S |
| AI-05 | タグ提案 | 指定したメモ | タグ2〜4件の候補（採用は利用者が選ぶ） | C |
| AI-06 | メモの構造化 | 同一テーマの複数メモ | 論点整理された階層構造（MECE な観点出し） | C |

**AI-05 の位置づけ変更**：v0.1 では「保存時に自動でタグを付与」（優先度 S）としていたが、
これは Q-6 の決定に反する自動送信にあたるため、**ボタン起動の「提案」機能に変更**し
優先度を C に下げた。

**AI-02 の起動タイミング**：確定直後に自動実行しない。
確定後の画面に「深掘りする」ボタンを置き、押された場合のみ送信する。

**AI-03 の追加要件**：対象メモが多い場合はトークン上限を考慮し、
件数上限（既定100件）または期間短縮を利用者に促す。

**送信前の明示**：各ボタンの近傍に、送信対象（「このメモ1件」「この期間の42件」等）を
文言として表示する。押す前に何が外部に出るかが分かる状態にする。

## 8. データ要件

### 8.1 保存形式

1メモ = 1 Markdown ファイル。YAML front matter にメタデータ、本文に内容を持つ。

```
data/
  memos/
    2026/
      09/
        20260910-070512_なぜ朝のメモ書きが続かないのか.md
        20260910-070634_続けるために減らせる手順は何か.md
  .draft.md          # 未確定の下書き（確定時に削除）
  .index.json        # 検索用キャッシュ（再生成可能）
```

**ファイル名規則**：`YYYYMMDD-HHMMSS_<タイトル>.md`

- タイトル部から OS の禁止文字（`\ / : * ? " < > |`）と制御文字を除去する
- タイトル部は60文字で切り詰める
- 同一秒に複数生成された場合は末尾に `-2`, `-3` を付す

### 8.2 ファイル内容

```markdown
---
id: 20260910-070512
created_at: 2026-09-10T07:05:12+09:00
edited_at: null
elapsed_sec: 47
target_sec: 60
input_method: voice
session_id: 20260910-070430
tags: [習慣, 朝]
---

# なぜ朝のメモ書きが続かないのか

- 起きてすぐノートを開く動作が1つ多い
- 「何を書くか」で30秒溶ける日がある
- 書いた紙が机に積まれるだけで読み返さない
- 続いているかどうかが自分で分からない
- 週末にまとめて書こうとして結局書かない
```

- `edited_at` は当日中の編集が行われた場合のみ値を持つ
- `input_method` は `voice` / `keyboard` / `mixed` のいずれか
- 本文の各行は箇条書き（`- `）とする。Obsidian 等でそのまま読める形を優先する

### 8.3 インデックス

**ファイルが唯一の正**であり、`data/.index.json` は起動時間短縮のためのキャッシュに過ぎない。
削除しても全ファイル走査により再生成できること。

- 起動時、`data/memos/` 配下の `.md` を走査し、mtime がキャッシュと異なるファイルのみ再読み込みする
- インデックスには front matter とタイトル、本文の全文を保持する
- 検索は インデックス上のインメモリ処理で行う

**規模の見積もり**（1日10枚・稼働率60%・1メモ約520バイトで試算）

| 経過 | メモ数 | 総容量 | 全ファイル走査の目安 |
| --- | --- | --- | --- |
| 1年 | 2,190 | 1.1 MB | 0.33 秒 |
| 3年 | 6,570 | 3.3 MB | 0.99 秒 |
| 5年 | 10,950 | 5.4 MB | 1.64 秒 |
| 10年 | 21,900 | 10.9 MB | 3.29 秒 |

mtime による差分読み込みを行うため、通常起動時の実コストは初回のみの上表を大きく下回る。
5年を超えて全走査が体感を損なう場合は、年単位のアーカイブ分割を検討する（第14章 Q-8）。

## 9. 技術構成

### 9.1 位置づけ

既存「AI ライティングツール」とは独立したアプリとする。
同一リポジトリ内に別エントリポイントとして配置し、Gemini クライアントのみ共有する。

```
shunpatsu_app.py            # 本アプリのエントリポイント（streamlit run の対象）
shunpatsu/
  memo_store.py             # Markdown ファイルの読み書きと検索（唯一の永続化層）

```

## 11. 制約・前提

- 単一利用者のローカル実行を前提とし、同時アクセス制御は行わない。
- **Streamlit は操作のたびにスクリプト全体を再実行する。** `st.text_area` は確定時にしか値を
  返さないため、1文字ごとの自動保存は標準機能では実現できない。ドラフト随時保存（FR-09）は
  `st.fragment(run_every="5s")` による部分再実行で実装し、画面全体の再描画を避ける。
- タイマーの精度は、再実行をまたいで保持した開始時刻との差分計算で担保する。
- 音声入力の品質・応答速度は OS の機能に依存し、本アプリの制御外である。
- Gemini API の利用にはネットワーク接続と有効な API キーが必要。
- 個人利用・非公開のため、アプリ名称「瞬発思考」に関する商標上の確認は行わない。
  公開・配布する場合は改めて確認を要する。

## 15. 受入基準（Phase 1）

1. 起動から2アクション以内でタイトル入力欄にフォーカスが当たっている。
2. OS の音声入力で本文を吹き込むと、通常のキー入力と同じく入力欄に反映される。
3. 最初の1文字の入力でタイマーが起動し、60秒を計測できる。
4. 60秒を超えても入力欄がロックされず、話し続けた内容が失われない。
5. 発話停止後に認識結果がまとめて流入しても、`elapsed_sec` に認識ラグが含まれない。
6. 最終入力から10秒間何も入力しないと、メモが自動確定される。
7. 句点を含む1行の本文が、保存時に句点位置で改行された Markdown として書き出される。
8. `Ctrl + Enter` でメモが確定し、空の新規メモが即座に表示される。
9. 確定したメモが `data/memos/YYYY/MM/` 配下に1ファイルとして存在し、テキストエディタで読める。
10. 入力途中でアプリを終了し再起動すると、その内容がドラフトとして復元される。
11. 当日中に確定したメモの誤変換を修正でき、`edited_at` が記録される。
12. 日付をまたいだメモが編集不可になっている（削除は可能）。
13. `GEMINI_API_KEY` を未設定にした状態でも、1〜12の全てが成功する。
14. テーマを入力して「お題を出す」を押すと AI がタイトル案10件を返し、1件を選ぶと SC-1 に反映される。
15. 確定直後の画面で「深掘りする」を押した時にのみ API へ送信され、押さなければ送信されない。
