# 要件定義書（案）：0秒思考メモ書きアプリ

| 項目 | 内容 |
| --- | --- |
| 文書名 | 0秒思考メモ書きアプリ 要件定義書（案 / v0.1） |
| ステータス | ドラフト（未レビュー） |
| 対象システム | 既存「AI ライティングツール」への機能追加、または同スタックでの単体アプリ |
| 想定技術スタック | Python 3.11+ / Streamlit / Google Gemini API / SQLite |

---

## 1. 背景と目的

### 1.1 背景

「A4用紙1枚に1テーマ、4〜6行、1分で書き切る」メモ書きトレーニング（いわゆる「0秒思考」メモ書き）は、
考えを寝かせずに即座に言語化することで思考速度と言語化能力を高める手法として広く知られている。

一方、紙で実践する場合には次の課題がある。

- **継続の可視化ができない** — 何ページ書いたか、続いているかが分からない
- **蓄積が死蔵する** — 書いたメモが物理的に埋もれ、振り返りに使われない
- **タイトルが出てこない** — 「何を書けばいいか分からない」で手が止まる
- **振り返りの負荷が高い** — 数百枚のメモから傾向を読み取るのは現実的でない

### 1.2 目的

本アプリは、メモ書きの**実践（書く）を紙と同等以上に軽量に保ちながら**、
紙では困難な**蓄積・検索・振り返り**を AI で支援することを目的とする。

### 1.3 成功指標（KPI 案）

| # | 指標 | 目標値（リリース3ヶ月後） |
| --- | --- | --- |
| K-1 | 1メモあたりの平均記入時間 | 60秒以内が全体の80%以上 |
| K-2 | 継続率（週3日以上メモを書いたユーザー） | 40%以上 |
| K-3 | 1日あたり平均作成メモ数 | 5ページ以上 |
| K-4 | 振り返り機能の月次利用率 | 継続ユーザーの50%以上 |

## 2. 設計思想（最重要の前提）

本アプリの機能取捨選択は、以下の原則を最優先で判断基準とする。

> **原則1：書いている最中に AI を介入させない。**
> メモ書きは「自分の頭で1分間ひねり出す」訓練である。執筆中のサジェスト・自動補完・添削は
> 手法の効果そのものを損なうため、**明確に対象外**とする。AI が働くのは「書き終わった後」だけ。

> **原則2：書き始めるまでの摩擦をゼロに近づける。**
> 起動から入力開始まで2アクション以内。ログイン・カテゴリ選択・設定を書く前に挟まない。

> **原則3：書いたメモは編集させない。**
> 推敲・清書はしない手法であるため、保存後の本文編集は既定で不可（削除とタグ付けのみ可）。

## 3. 用語定義

| 用語 | 定義 |
| --- | --- |
| メモ | タイトル1行＋本文4〜6行からなる、1テーマ1ページの記録単位 |
| セッション | 連続してメモを書く一連の時間（既定：10ページ / 約10分） |
| お題（タイトル案） | これから書くメモのタイトル候補 |
| 深掘り | 書いたメモの内容から派生する次のメモのタイトルを導くこと |
| 振り返り | 一定期間に蓄積したメモを対象とした要約・傾向分析 |

---

## 4. スコープ

### 4.1 対象（本リリース）

- メモの作成・保存・一覧・検索・削除
- 1分タイマーとセッション管理
- AI によるお題出し・深掘り・タグ付け・振り返り
- ローカル単一ユーザー利用（`streamlit run` によるローカル起動）

### 4.2 対象外（本リリース）

- 複数ユーザー / 認証 / チーム共有
- 手書き入力・OCR・音声入力
- モバイルネイティブアプリ
- クラウド同期・バックアップ
- 執筆中の AI サジェスト（原則1により恒久的に対象外）

## 5. 想定利用者と利用シーン

### 5.1 ペルソナ

| # | 像 | 主な動機 | 主な障壁 |
| --- | --- | --- | --- |
| P-1 | 思考の言語化を鍛えたい20〜40代のビジネスパーソン | 会議・資料作成で即答できるようになりたい | 続かない、書くネタが出ない |
| P-2 | 悩み・モヤモヤを整理したい人 | 頭の中を吐き出して落ち着かせたい | どこから手をつけるか分からない |
| P-3 | 既に紙で実践中の人 | 蓄積を検索・振り返りに活かしたい | 紙が死蔵する |

### 5.2 代表的な利用シーン

1. **朝10分**：アプリを開き、AI にお題を10個出させ、順に1分ずつ書き切る。
2. **モヤモヤ発生時**：思いついた瞬間にタイトルだけ書いて即座に本文を吐き出す。
3. **週末の振り返り**：直近1週間のメモを AI に要約させ、繰り返し現れる論点を確認する。

## 6. 機能要件

優先度は MoSCoW（M=必須 / S=推奨 / C=可能なら / W=今回対象外）で示す。

### 6.1 メモ作成

| ID | 機能 | 内容 | 優先度 |
| --- | --- | --- | --- |
| FR-01 | メモ入力 | タイトル1行＋本文の入力。本文は4〜6行を推奨として提示 | M |
| FR-02 | 行数ガイド | 現在の行数を表示。3行以下／7行以上は警告表示（保存は妨げない） | S |
| FR-03 | 1分タイマー | 入力開始と同時に自動起動する60秒カウントダウン。残り10秒で色変化 | M |
| FR-04 | タイマー超過の扱い | 0秒到達で入力をロックしない。経過秒数を記録し保存時に表示 | M |
| FR-05 | 保存 | `Ctrl + Enter` で保存し、即座に次の空メモへ遷移（連続記入） | M |
| FR-06 | 編集禁止 | 保存済みメモの本文・タイトルは編集不可（原則3） | M |
| FR-07 | 削除 | 保存済みメモの削除は可能（確認ダイアログあり） | M |
| FR-08 | 下書き復帰 | 未保存のまま画面遷移・リロードした場合に入力内容を復元 | S |

### 6.2 セッション管理

| ID | 機能 | 内容 | 優先度 |
| --- | --- | --- | --- |
| FR-10 | セッション開始 | 目標ページ数（既定10）を指定してセッションを開始 | S |
| FR-11 | 進捗表示 | 「3 / 10ページ」の進捗と累計経過時間を表示 | S |
| FR-12 | セッション完了 | 目標達成時に完了サマリー（所要時間・平均秒数）を表示 | C |
| FR-13 | 連続日数 | 連続実施日数（ストリーク）と月間カレンダーを表示 | C |

### 6.3 蓄積・検索

| ID | 機能 | 内容 | 優先度 |
| --- | --- | --- | --- |
| FR-20 | メモ一覧 | 作成日時の降順で一覧表示。日付単位でグルーピング | M |
| FR-21 | キーワード検索 | タイトル・本文に対する部分一致検索 | M |
| FR-22 | タグ絞り込み | タグによる絞り込み | S |
| FR-23 | 期間絞り込み | 期間指定（今日 / 今週 / 今月 / 任意範囲） | S |
| FR-24 | エクスポート | 選択範囲を Markdown / CSV でダウンロード | S |
| FR-25 | インポート | 既存のテキスト・CSV からの一括取り込み | C |

### 6.4 AI 支援機能

すべて **メモを書いた後、またはメモを書く前** にのみ動作する（執筆中は動作しない）。

| ID | 機能 | 入力 | 出力 | 優先度 |
| --- | --- | --- | --- | --- |
| AI-01 | お題出し | テーマ・悩み（自由文） | メモタイトル案10件 | M |
| AI-02 | 深掘り質問 | 直前に保存したメモ | 次に書くべきタイトル案3件 | M |
| AI-03 | 自動タグ付け | 保存されたメモ | タグ2〜4件（保存時に非同期付与） | S |
| AI-04 | 期間振り返り | 指定期間のメモ群 | 論点の要約・繰り返し現れるテーマ・気づき | M |
| AI-05 | メモの構造化 | 同一テーマの複数メモ | 論点整理された階層構造（MECE な観点出し） | C |
| AI-06 | モヤモヤ分解 | 漠然とした悩み1件 | 具体的な問いに分解したタイトル群 | S |

**AI-04 の追加要件**：対象メモが多い場合はトークン上限を考慮し、
件数上限（既定100件）または期間短縮を利用者に促す。

### 6.5 設定

| ID | 機能 | 内容 | 優先度 |
| --- | --- | --- | --- |
| FR-30 | タイマー秒数 | 既定60秒。30〜180秒で変更可 | S |
| FR-31 | 1日の目標ページ数 | 既定10ページ | S |
| FR-32 | AI 機能の一括 OFF | API キー未設定時も執筆機能は完全に動作すること | M |

## 8. データ要件

### 8.1 論理データモデル

```
memo
  id           TEXT   PK   -- UUID
  title        TEXT   NOT NULL
  body         TEXT   NOT NULL   -- 改行区切りの本文
  line_count   INTEGER NOT NULL
  elapsed_sec  INTEGER NOT NULL  -- 記入に要した秒数
  created_at   TEXT   NOT NULL   -- ISO 8601
  session_id   TEXT   NULL   FK -> session.id

tag
  id           TEXT   PK
  name         TEXT   NOT NULL UNIQUE
  source       TEXT   NOT NULL   -- 'user' | 'ai'

memo_tag
  memo_id      TEXT   FK -> memo.id
  tag_id       TEXT   FK -> tag.id
  PRIMARY KEY (memo_id, tag_id)

session
  id           TEXT   PK
  started_at   TEXT   NOT NULL
  ended_at     TEXT   NULL
  target_count INTEGER NOT NULL
```

### 8.2 保存方式

- 保存先：プロジェクトルート配下の SQLite ファイル（例：`data/memos.db`）
- `.gitignore` に `data/` を追加し、メモ本文をリポジトリにコミットしない
- 保存は同期処理とし、AI タグ付け（AI-03）は保存完了後に別途実行する

## 9. 外部インターフェース / 技術構成

### 9.1 構成

既存リポジトリの構成を踏襲する。

```
app.py  →  tools/<tool>.py  →  utils/gemini_client.generate()  →  Gemini API
                            ↘  utils/memo_store.py  →  SQLite
```

- `tools/zero_second_thinking.py` … AI-01〜AI-06 のプロンプト構築関数群
- `utils/memo_store.py` … 新規追加。CRUD と検索を担う唯一の永続化層

### 9.2 外部 API

| 項目 | 内容 |
| --- | --- |
| API | Google Gemini API（`google-genai`） |
| モデル | `gemini-2.5-flash`（既定） |
| 認証 | `.env` の `GEMINI_API_KEY` |
| 失敗時 | 執筆・保存機能は継続動作させ、AI 機能のみエラー表示に留める |

## 10. 非機能要件

| ID | 分類 | 要件 |
| --- | --- | --- |
| NFR-01 | 応答性 | 文字入力からの画面反映は体感遅延なし。保存処理は 300ms 以内 |
| NFR-02 | 応答性 | AI 機能の応答は 10 秒以内を目標。処理中はスピナーを表示 |
| NFR-03 | 可用性 | ネットワーク不通・API キー未設定でも FR-01〜FR-25 は全て動作すること |
| NFR-04 | データ保全 | 保存済みメモは利用者の明示的な削除以外で失われないこと |
| NFR-05 | プライバシー | メモ本文は外部送信しない。ただし AI 機能実行時は対象メモのみ API へ送信され、その旨を画面に明示する |
| NFR-06 | プライバシー | API キーは `.env` のみで管理し、ログ・画面・リポジトリに出力しない |
| NFR-07 | 保守性 | 新規 AI 機能の追加は `tools/` へのプロンプト関数追加のみで完結すること |
| NFR-08 | 対応環境 | Windows / macOS のデスクトップブラウザ最新版 |
| NFR-09 | 国際化 | UI・生成物ともに日本語のみ（多言語対応は対象外） |

## 11. 制約・前提

- 単一利用者のローカル実行を前提とし、同時アクセス制御は行わない。
- Streamlit は操作のたびにスクリプト全体を再実行するため、タイマーとセッション状態は
  `st.session_state` で保持する必要がある。タイマーの精度は開始時刻との差分計算で担保する。
- Gemini API の利用にはネットワーク接続と有効な API キーが必要。
- 「0秒思考」は書籍で提唱された手法名であり、アプリ名称としての利用可否は
  商標・権利面の確認を要する（第13章 未決事項 Q-1）。

## 14. 受入基準（Phase 1）

1. 起動から2アクション以内でタイトル入力欄にフォーカスが当たっている。
2. 入力開始と同時にタイマーが起動し、60秒を計測できる。
3. `Ctrl + Enter` でメモが保存され、空の新規メモが即座に表示される。
4. アプリを再起動しても保存済みメモが全件残っている。
5. 保存済みメモの本文が編集できない。
6. `GEMINI_API_KEY` を未設定にした状態でも、1〜5の全てが成功する。
7. テーマを入力すると AI がタイトル案10件を返し、そのうち1件を選ぶと SC-1 に反映される。
8. 保存直後に、そのメモに基づく深掘りタイトル案が3件表示される。
